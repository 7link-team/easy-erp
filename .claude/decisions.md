# Decisions

## 物料候选与业务资料
Decision: 单独 material_options 表，仅提供候选，业务继续保存字面值与历史快照。
Reason: 用户明确允许删除只影响列表；避免批量改动库存单位和历史资料。
Alternatives Considered: 业务全部关联可变字典 ID，改名自动同步。
Tradeoffs: 纠正物料实际值必须从物料编辑，候选改名不会自动修复现有物料。
Scope: 规格、类型、单位。
Status: 用户授权设计关联影响处理，实施方案已说明。

## 单据类型
Decision: 沿用 sales_catalog，开单手输在命令事务内新增；必须明确是否计款；已停用类型拒绝新用，管理修改限管理员。
Reason: 复用现有 ID/规则与历史快照，避免名称猜测财务行为。
Scope: 本次单据类型可输入要求。
Status: 实施。

## 导航
Decision: 客户与基础资料独立一级菜单，基础资料内采用共享字典管理器（2026-10-10 后续用户明确要求按 v2 原型恢复左清单右表格，替代早期水平 Tab）。
Reason: 用户要求减少层级；客户原文无深层设计限制。
Scope: 客户、基础资料、库存快捷开单。
Status: 实施。


## 2026-10-10 设计收尾与登录

Tradeoffs: 反向代理须保持外部 Host 与 Origin 一致。
Scope: vite.config.ts、开发代理 E2E。
Status: 已实现并验证。

## 2026-10-10 侧栏与工作台反馈
Decision: 桌面侧栏只让 nav 滚动，品牌标题与底部说明固定；开单发货复用 task-card，并入工作台常用操作网格。

Tradeoffs: 电脑宽屏四个入口同排，手机两列；按现有权限显示入口。
Scope: App、现有样式和相关 UI 回归。
Status: 已实现，真实浏览器截图及 Chromium / WebKit 相关测试通过。

Tradeoffs: 一次选择一个物料，已选物料禁用，数量在原行修改。
Scope: SaleEditor、现有 Popover 和共享表单样式。

## 2026-10-10 自定义角色与模块权限
Decision: 用户明确授权本轮实现。新增 roles 表与 roles_v1 迁移，users.role 继续保存角色 ID；admin 为受保护系统身份。角色权限由后端目录统一提供，前端按目录显示模块动作并选中依赖权限，后端独立校验。账号创建/维护、角色维护与主机操作仍限管理员。
Reason: 允许用户维护实际岗位角色，避免仅用三个库存复选框描述全部业务。普通角色不能通过角色维护升级为系统管理员。
Alternatives Considered: 仅新增前端权限复选框无法防止 API 越权；覆盖旧账号权限会改变历史授权，均不采用。
Tradeoffs: users 的历史列及旧 worker/viewer API 兼容；升级将 worker 八种组合分别映射为可维护角色，viewer 始终只读；保留原来的本人单据范围。角色变更撤销成员会话。已关联账号的角色须先转移成员才能删除。
Scope: 物料、物料字典、收发库存、操作记录、清点、销售单据、客户、业务资料、资金账户、财务报表。业务删除沿用停用/作废，退款为独立授权，修订/退货/作废产生退款同样检查退款权限。角色数据纳入完整备份，旧备份在临时副本迁移后恢复。
Status: 已实现并交付2211f46；迁移组合、直接API鉴权、角色备份恢复和浏览器回归通过。

## 2026-10-10 统一收发与财务分区
Decision: 入库/出库与开单共用 ItemPicker 和 document.css；明细列表末尾添加一行、行内更换/删除，固定标题和最终操作；入库允许零库存，出库和销售禁止选择零库存。财务按用户确认采用同页三分区。
Reason: 用户确认库存跳转已带入物料，但原两栏布局导致不易辨认；统一编辑方式并明确业务分区。财务减少二级 tab 切换。
Scope: 表单结构、间距、选料行为及财务展示；保留业务事务与预选参数。
Status: 已实现并交付2211f46；更正流水无可选记录时禁用并说明原因，只列未冲销原流水，相关浏览器回归通过。

## 2026-10-10 原型结构对齐
Decision: 用户指出基础资料及多处结构未按 v2 原型实施，现以 prototype.html 为布局依据。基础资料为左清单/右账册/底部新增；客户及单据以真实字段列展示；列表表格消除重复边框和水平内边距。手机字典横向选择、行内字段和操作，列表只保留一层内容留白。
Reason: 仅套用主题令牌不代表页面结构符合设计。通过参考与实装截图以及实际边距测量核对。
Alternatives Considered: 继续保留水平标签和拼接文字行，用户明确否定。
Tradeoffs: 不复制原型占位数或未实现的导入/拖拽等动作，不改变物料候选删除和历史快照规则。保留用户已明确批准的逐行选料、财务同页分区和自定义角色。
Scope: 已有页面的布局/可访问性及回归验证，不增加新的业务模块或修改财务规则。
Status: 此处列明的首批结构已实现并通过浏览器验证；完整原型功能差异继续按task-state.md补齐。

## 2026-10-10 原型与原始业务需求的优先级
Decision: 原型决定视觉布局，不自动成为新增会计或考核规则的依据。用户对新增目标管理提出质疑后，重新核对 20261009.md：要求业绩归属，没有销售目标。成本和目标扩展暂停，尚未修改模型或代码。
Reason: “全部做到位”应是完整实现真实要求，不能把原型演示字段推断成客户未要求的新系统。现金实收与应收必须区分，历史记录不可随现值变化。
Scope: 暂不实施成本算法/目标考核；继续现有业务功能缺口与原型视觉对齐。
Status: 按用户最新纠正执行；成本是否继续及核算口径尚未确认，其他工作继续。

## 2026-10-10 开单结算与欠款凭据
Decision: 新建及草稿编辑明确全部欠款/部分收款/全额收款；金额不超过应收，欠款由应收减实际收款计算。收款账户明确选择，日期取业务日期。复用 command 事务同时扣库存与写 cash，沿用 sales.pay 权限；草稿保存待登记内容，实际财务金额仍为零，确认后清除待登记字段。
Reason: 用户明确指出缺少欠款选项，原始需求举例 10050 抹零 50、实收 5000、欠款 5000。
Tradeoffs: 复用现有单账户收款输入；可在单据详情继续分账户补收。打印按当前单据版本显示实际欠款及客户签字确认，照片复用现有两张附件能力，不强制上传。
Scope: 开单结算、欠款打印和签字照片流程；不扩展成本或目标管理。
Status: 实现并验收；Chromium/WebKit 各31项与最终补测各3项通过，实际 PDF 和照片上传通过。

## 2026-10-10 原型查询与手机滚动
Decision: 物料状态/排序、单据状态/日期、收发和审计查询复用现有列表接口；导出与列表共用服务端筛选谓词。筛选和页码保存在 URL，查询不新增浏览器历史项。停用物料按版本号恢复启用并记录审计。
Reason: 原型已有对应查询入口，单纯显示筛选或导出全量数据不能满足实际核对。单据状态与收款状态分别展示，草稿不能显示为已经记账。
Tradeoffs: 沿用导出仅管理员、本人记录范围和现有表结构；停用物料不进入开单/收发候选。恢复沿用 items.update，不扩大权限。没有引入成本或目标规则。
Scope: 物料、单据、记录列表及现有表格导出。窄屏 app-shell 改为内容区与底部导航两行，内容只在导航上方滚动，修复筛选变高后末行操作被遮挡；仅 screen 媒体生效，不影响打印。
Status: 已实现并验收；Chromium/WebKit各52项、显示组合检查与本地嵌入式预览通过。整体原型对齐继续。

## 2026-10-10 客户往来与业务表格入口
Decision: 客户档案按客户 ID 复用财务汇总，展示应收/净实收/欠款；对账复用 CustomerLedger，客户上下文写入 URL，进入单据补收后返回原客户。没有 finance.read 不显示金额，没有 sales.read 不提供单据入口，仅本人权限明确提示范围。
Reason: 原型客户表已有账款与对账入口，现有数据和权限足以实现，不能按名称混账或因显示汇总自动扩展单据权限。
Tradeoffs: 复用现有财务接口；汇总为全部有效单据，明细仍受原有 sales.all 范围约束。历史关联数量与当前账款明细的统计用途不同。
Scope: 客户账册、销售筛选导出、物料页导入。导出复用服务端筛选和余额计算，草稿/作废记账金额为零，原单金额单列，整数分精确格式化。TableImport 从原备份页提取供物料弹窗共用，保留模板、检查、预览、确认事务和管理员权限。
Status: 已实现并验收；Chromium60及导入补测2通过。WebKit发现搜索竞争后修复，受影响套件36通过；最终手机对账Chromium/WebKit各2通过，显示检查及Excel下载验证通过。详细分批结果见task-state.md。

## 2026-10-10 退货与作废汇总
Decision: 复用sales_revisions中的return/void记录，只投影汇总所需字段；应收变化与实际退款分别取当时before/after差额，沿用sales.read和父单sales.all/本人范围，点原单复用详情。

Scope: 只读汇总、导航和复用详情；不改变退货/作废事务及授权。
Status: 已实现并验收；历史金额/51次分页/本人范围通过，最终Chromium93/WebKit93及显示检查通过。

## 2026-10-10 请求取消与过期响应
Decision: api读取正文遇AbortError继续抛出，其他无效JSON作为ApiError；useResource仅在未取消时接受成功结果。401继续触发原会话失效流程，不依赖响应正文是否可解析。
Reason: 实际回归trace证明快速筛选取消正文读取后，原catch生成的error对象被当作成功列表写回，造成items.length崩溃。
Tradeoffs: 保持既有fetch/AbortController机制，修复共享入口，不为每页添加临时防御字段或改变成功数据结构。
Scope: 请求正确性和当前查询/页面回归；不改变服务端权限或API业务规则。
Status: 最小修复、原失败场景和受控专项已通过，完整Chromium93/WebKit93通过。

Scope: GlobalSearch、顶栏入口、现有列表定位和客户查询、同条件导出与浏览器回归。
Status: 已实现并验收；最终Chromium44/WebKit44、Rust7与72组显示检查通过。URL筛选仅在地址实际变化时replaceState，避免WebKit历史API调用频率限制；不改变返回状态或引入等待。

## 2026-10-10 客户与基础资料批量维护
Decision: 客户、单据类型、收款账户、部门、业务员及规格/分类/单位提供CSV/XLSX模板、预览确认导入与导出；公司单例继续原表单。导入按已有create权限、导出按read权限，停用记录仍需update；原物料/期初导入权限不变。
Reason: 原型批量入口缺失，必须同时落实真实保存规则及权限，不能仅做界面按钮。
Alternatives Considered: 每行独立事务会导致部分成功；直接覆盖同名资料会改变既有规则；均不采用。
Tradeoffs: 每次最多100行/5MB，姓名/名称重复报错，业务员按已有启用部门完整名称关联；预览记录部门ID，确认时防止改名后旧名称被其他部门复用而悄悄改归属。预览在回滚事务中使用同一保存核心，确认取得写锁后再次鉴权、重新校验并整批提交；既有请求表保证重复确认幂等。
Scope: 复用transfer解析/导出/任务存储、sales/options保存核心、TableImport/Modal。客户导出遵循当前搜索和精确ID定位，字典按当前类别；不新增schema、不写历史单据、不改变候选和物料之间的关系。
Status: 已实现并验收；相关WebKit77、最终专项Chromium7/WebKit7、Rust7通过；Chromium相关回归与catalog5补测通过，216显示组合和36嵌入预览组合通过。

## 2026-10-10 字典管理字段与原子排序
Decision: 规格/分类/单位增加启停、排序、说明、来源、最近使用和当前物料引用数；来源仅记录升级后的手工录入/自动收录/表格导入，旧值未知。最近使用指新增或改选物料时实际使用该候选。只读物料账号仅取得选择所需字段，引用数还需items.read与options.read。账户类型为可维护文字字段。
Reason: 补齐原型基础资料管理，并保证展示是真实业务数据，不伪造升级前的来源和时间。
Alternatives Considered: 按现存物料推测旧来源/日期会误导；逐行独立排序可能部分保存；均不采用。
Tradeoffs: 候选引用数按当前物料文字规范化匹配，包含停用物料，不冒充历史单据引用。候选改名/删除不改物料或历史；停用拒绝新选用，旧物料未改值可保留。旧接口省略新增字段时保留已有值；单列候选/四列账户模板与既有预览兼容。
Scope: metadata增量迁移及已知旧备份升级；资料按完整ID/version清单在同一事务排序，冲突时不改变顺序。拖拽提供上下按钮作为键盘/触屏替代，排序后恢复键盘焦点并播报。成本/目标仍暂停。
Status: 已实现并验收；相关Chromium71/WebKit71、最终UI补测Chromium29/WebKit6、Rust7通过；192显示组合与最后账户48组合通过，详情见task-state.md。
