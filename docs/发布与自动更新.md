# 多平台构建与自动更新

## 构建入口

推送 `main`、提出 PR 或在 Actions 手动运行 **Build and release**，生成 Web zip、Windows x64 NSIS exe、macOS Intel/Apple Silicon dmg、Linux x64 AppImage/deb、Android 包及 iOS 模拟器包。桌面构建同时提供对应平台的独立库存服务 tar.gz，已内嵌 Web，供不运行桌面界面的电脑部署。产物先保存在该次 Actions 的 Artifacts 中。

Android 没有正式密钥时仅生成调试 APK，不能作为正式更新基线。iOS 真机签名没有配置时跳过 IPA 构建，不用模拟器包冒充真机安装包。Windows/macOS/Linux 初次成功构建后仍需对应系统实机验收。

版本标签 `v版本号` 触发 Release 草稿。标签必须与 `desktop/tauri.conf.json` 一致；前端 `package.json`、根 `Cargo.toml` 的 workspace version、`desktop/Cargo.toml` 及各自锁文件也应同步更新。发布需要所有启用的构建成功、固定 Android 签名及四种桌面更新签名，任一缺失不生成更新清单。

草稿不会触发客户端自动更新。验收后正式发布 Release，客户端才会通过 `releases/latest/download/latest.json` 获取新版。不允许重跑任务覆盖已正式发布的同版本资产；修复应增加版本号。

## 稳定版与测试版渠道

桌面「版本更新 → 更新渠道」可选择稳定版（默认）或测试版，本机独立保存。切换后立即重新检查；如果已经下载更新包，需确认清除旧渠道的包。检查、下载或安装进行中不能切换。旧版桌面壳尚未支持渠道命令时不显示选择器；Web 与手机不提供桌面更新渠道选择。

- 稳定版：使用 GitHub `releases/latest/download/latest.json`，并在客户端按 SemVer 再次排除所有预发布版本，即使清单被误放进正式 Release，也不会安装 Beta/RC。
- 测试版：匿名查询该仓库最近 100 条公开 Release，排除草稿及没有 `latest.json` 的版本，按 SemVer 选取最高版本（包括正式版与预发布版），再读取该版本的固定下载地址。查询和下载都保留代理优先、失败直连、版本签名校验。GitHub API 限流或两条线路失败时显示重试，不把失败当作没有更新。
- 两种渠道都只安装严格更高的版本。测试版切回稳定版不会自动降级，需等待稳定版版本号超过当前版本，以免旧程序与已迁移数据库不兼容。

正式版本标签例如 `v0.2.0`，预发布标签例如 `v0.2.0-beta.1`、`v0.2.0-rc.1`。流水线统一检查标签与应用版本一致、版本号符合 SemVer；带预发布部分的版本自动标记 GitHub Pre-release，并设置不作为 Latest。所有必需构建与检查成功后仍只创建草稿，验收后才发布。将 RC 提升为正式版需使用新的正式版本号重新构建、签名，不能仅去掉旧 Release 的 Pre-release 标记。

桌面流水线现在同时执行本机架构的渠道隔离、下载回退和签名校验单元测试。构建失败保留既有已发布版本；渠道隔离并不意味着构建或软件永远不会出错。

## GitHub 权限和下载地址

SSH key 只用于 Git 推送。管理 Actions、仓库变量和 Secrets 需要 GitHub CLI/API 授权。当前发布地址为 `https://github.com/7link-team/easy-erp/releases`，同仓库发布使用 Actions 自带的 `github.token`，不需要额外的 `RELEASE_TOKEN`。客户端匿名下载要求仓库公开；私有仓库的下载不能通过把 GitHub Token 内置客户端来解决。

在源码仓库的 **Settings → Secrets and variables → Actions** 配置：

| 类型 | 名称 | 用途 |
| --- | --- | --- |
| Variable | `RELEASE_REPOSITORY` | `7link-team/easy-erp` |
| Secret | `RELEASE_TOKEN` | 当前同仓库发布不需要；仅跨仓库时配置限权凭据 |
| Variable | `UPDATER_ENDPOINT` | `https://github.com/发布仓库/releases/latest/download/latest.json` |
| Variable | `UPDATER_PUBLIC_KEY` | Tauri 更新公钥 |
| Secret | `TAURI_SIGNING_PRIVATE_KEY` | Tauri 更新私钥内容，不是文件路径 |
| Secret | `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 更新私钥密码，未设置密码时留空 |

Tauri 更新签名用于校验下载包，独立于 Apple、Windows 系统签名。密钥必须长期保存；随意更换会让旧客户端无法验证更新。密钥和生产数据库不进 Git。

## Android 正式签名

设置 `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 四个 Secrets。默认 keystore 类型为 PKCS12，已有 JKS 密钥时将 `ANDROID_KEYSTORE_TYPE` Variable 设为 `JKS`。每个版本使用同一密钥，以便在手机上覆盖安装。构建生成含 ARM64、ARMv7 和 x86_64 的包。

首次发布可在本机运行 `node scripts/create-signing-keys.mjs`。脚本在用户目录 `.config/easy-erp/signing/` 生成并保留更新密钥及 Android PKCS12 身份（别名 `easy-erp`），不覆盖已有密钥。Android 的 store/key 密码相同，保存在该目录的 `android-password` 文件。私钥与密码需另行备份并通过 GitHub CLI 标准输入或 GitHub Secrets 页面配置，不要贴到聊天或提交到 Git。

移动客户端不内置 SQLite、服务程序、托盘或开机自启；连接已运行的库存电脑。应用会记住连接地址，顶部「连接设置」可更换。由于局域网服务使用 HTTP，Android 允许明文连接，iOS 声明局域网用途及 WebView 的 HTTP 支持；公网访问应部署 HTTPS。

iOS 内部产品名保持 ASCII `EasyERP`，通过 `CFBundleDisplayName` 显示“库存管理”。不要把内部产品名改成中文：Apple 的 `NSBundle bundleWithIdentifier` 在解析非 ASCII 可执行文件路径时可能崩溃，影响 Tauri 启动时读取 WebKit 版本。模拟器任务除编译外还执行安装、启动、存活检查，并上传截图和诊断日志；模拟器包使用本地 ad-hoc 签名，不需要开发者账号。

## Apple 签名

macOS 未配置正式身份时使用 ad-hoc 签名，会受系统未认证应用策略影响。Developer ID 分发需配置：

- `APPLE_CERTIFICATE`、`APPLE_CERTIFICATE_PASSWORD` Secrets：Developer ID Application p12 的 Base64 内容及密码。
- `APPLE_SIGNING_IDENTITY` Variable：完整 Developer ID Application 身份。
- `APPLE_ID`、`APPLE_PASSWORD` Secrets：Apple ID 和专用密码；`APPLE_DEVELOPMENT_TEAM` Variable：团队 ID，用于公证。

iOS 真机需另外配置 `IOS_CERTIFICATE_BASE64`、`IOS_CERTIFICATE_PASSWORD`、`IOS_PROFILE_BASE64` Secrets，`APPLE_DEVELOPMENT_TEAM` 和 `IOS_SIGNING_ENABLED=true` Variables。应用标识为 `com.aspeed.easy-erp`。当前 IPA 按 release-testing 导出，描述文件必须包含允许安装的设备；App Store 分发需改用 app-store-connect 描述文件/导出方式，并另行提交审核。iOS 不通过 Tauri updater 安装新版。

Windows 当前可生成安装包，Authenticode 代码签名尚需选定证书/签名服务；未签名安装器可能出现系统信誉提示。

Windows x64 的桌面和服务构建共用根目录 `.cargo/config.toml`，静态链接 Visual C++ 运行库，避免新电脑因缺少 `VCRUNTIME140.dll` 无法启动。不要用环境变量 `RUSTFLAGS` 覆盖这项配置。流水线通过 `scripts/check-windows-runtime.ps1` 检查实际桌面程序、打包的内置服务和独立服务的常规及延迟 DLL 导入；发现外部 VC 运行库依赖即阻止发布。此检查允许 Windows 自带的系统 DLL，不代替目标系统实机验收。

## 桌面更新流程

启动客户端后每日最多自动检查一次；顶部下载图标可随时手动检查。下载期间可继续操作，界面显示进度；Tauri 验证签名后才允许安装。未提交的收发表单阻止安装，用户须先完成或取消操作。

「版本更新」页面提供手动检查、下载、安装和更新说明，手机入口在「更多」。选择稍后更新或切换页面不会丢失本次下载状态。

页面和更新弹窗分别显示检查、下载的实际线路及连接中、成功、失败状态，回退后保留切换标记。这些信息由原生请求上报；本次打开尚未请求时明确显示尚未检查或下载，不将默认代理策略当作已经连接成功。

GitHub Release 的检查和下载均优先走 `https://gh-proxy.com/`，失败后自动回退 GitHub 原始地址。构建变量 `UPDATER_ENDPOINT` 和发布清单仍填写原始 GitHub URL，由客户端统一生成代理地址；本地测试及其他域名不会发往代理。检查每条线路最多等待 12 秒；下载连接最多等待 8 秒、连续 15 秒未收到数据则换线路，每条线路总下载上限为 15 分钟。切换下载线路会从头下载，界面重置进度并提示已切换直连。

代理返回错误页面、HTTP 错误、网络异常，或下载包签名不匹配，均会触发回退；两条线路都失败时保留当前应用并显示重试提示。代理只传输公开的版本清单和安装包，不接收库存数据或应用登录凭据。安装包和声明版本始终由 Tauri 官方更新器验签，代理不能代替发布签名；代理缓存可能延迟新版本可见时间，合法的「暂无更新」响应不会触发回退。

确认安装时会提醒多人共享中断。本机存在库存数据库时，先让当前服务完成进行中的请求，生成可恢复的 ZIP 备份，阻止后续操作，再优雅退出。应用等待数据目录锁释放后才调用安装器，避免 Windows 服务可执行文件仍被占用。安装失败会尝试重新启动库存服务；成功重启后恢复服务，即使桌面此前切换到了远端连接。

本地控制接口只接受回环连接和本机持有的随机密钥，浏览器管理员登录不等于服务更新权限；密钥不会返回 Web 页面。旧版没有这个接口的服务需要先手动退出，不能强杀后假定已经备份。

托盘提供两个明确选项：“仅退出界面（共享继续）”保留本机服务；“全部退出（停止本机共享）”先备份并等待服务退出。关闭窗口仍只隐藏到托盘。

Windows 手动 EXE 和应用内更新都先验证本机库存身份、备份并优雅停止旧服务，再关闭对应安装目录的桌面进程，禁止按进程名批量强杀服务。离线数据库由新包中的 `--backup-only` 工具持有目录锁、生成标准 ZIP，且不运行数据库迁移。备份或停止失败即中止安装；库存与备份目录永不由安装器删除。安装器直接覆盖升级，不再调用旧卸载器，卸载页面也不再提供删除应用数据选项。交互安装完成页默认启动新版；自动更新使用 Tauri 的 `/UPDATE /R` 流程重启。

定制 NSIS 模板基于 Tauri CLI 2.12.1，来源与许可证保存在 `desktop/windows/`。升级固定的 CLI 版本时须同步复核模板。Windows CI 实际执行旧版后台服务运行时的覆盖安装、自动更新参数及重启、卸载后库存保留检查。

Linux 自动更新仅适用于 AppImage，deb 使用系统包管理或下载新版安装。Web 在窗口重新获得焦点及每五分钟检查服务版本，发现升级后提示刷新；未提交收发内容会阻止刷新。Android 使用相同签名 APK 或商店更新；iOS 使用相应 Apple 分发渠道。

## 验证命令

```sh
npm run build
cargo build --locked -p easy-erp-server
cargo test --locked -p easy-erp-server
node --test scripts/tests/*.test.mjs
cargo test --locked --manifest-path desktop/Cargo.toml --lib
```

更新协调测试使用随机端口和临时数据库，验证错误凭据被拒、备份生成、服务正常退出、重启后物料和会话仍有效。Playwright 仍仅保留在本地，不加入仓库。
