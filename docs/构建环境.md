# 构建环境与平台边界

Docker 固定 Web 与 Linux 服务端的编译环境。用户电脑只需运行交付的程序，不需要 Node、Rust 或 Docker。低配工人电脑不承担编译工作。

## Docker 构建

仓库根目录执行：

```sh
docker build --target artifacts --output type=local,dest=build-artifacts .
```

Docker Hub 无法访问时，可显式使用 AWS Public ECR 的 Docker Official Images 镜像，不改动全局 Docker 设置：

```sh
docker build --build-arg BASE_REGISTRY=public.ecr.aws/docker/library \
  --target artifacts --output type=local,dest=build-artifacts .
```

Dockerfile 固定 Node 24.14.0、Rust 1.99.0 与 Debian Bookworm 基础环境，npm/Cargo 使用锁文件。构建执行 Web 类型检查、Web 打包、Rust 单元测试及 Linux 服务端 release 编译。Playwright 配置、测试代码和报告仅保留在本地，因此 Docker 构建不再依赖这些文件，成品启停与浏览器验收需另行执行。缓存保存在 BuildKit 中，默认只用 2 个 Rust 编译任务，可通过 `--build-arg BUILD_JOBS=4` 修改。

产物：

- `build-artifacts/linux/easy-erp-server`：内嵌 Web 的 Linux 服务程序，架构与 Docker 的构建平台相同。不是 macOS/Windows 程序。
- `build-artifacts/web/`：单独的 Web 静态资源。

镜像标签固定版本，但不是内容摘要锁定；需要严格供应链复现时，须将验证过的基础镜像摘要写入发布配置。首次构建需要拉取镜像、依赖及完整编译，Docker 不保证比本机首次编译快。在 macOS 上还会占用 Linux 虚拟机内存。

此 Dockerfile 用于编译，不包含生产容器部署或数据库挂载。不要将编译容器作为库存主机使用。生产容器部署还需完成初始化管理通道、持久卷、备份和权限配置的专门验收。

## 桌面平台

| 交付物 | 构建环境 | 运行验收 |
| --- | --- | --- |
| Web | Docker 或 Node | 真实浏览器连接实际服务 |
| Linux 服务端 | Linux Docker | 启停、持久化、备份恢复 |
| macOS 桌面及内置服务 | macOS + Xcode + Rust + Node | 窗口、托盘、自启、服务生命周期 |
| Windows 桌面及内置服务 | Windows + MSVC + Rust + Node | WebView2、托盘、自启、服务生命周期 |
| Linux 桌面及内置服务 | Linux + WebKitGTK/GTK + Rust + Node | 桌面环境、托盘兼容性、服务生命周期 |

Linux 桌面也可在配置了系统依赖的 Docker 内编译，但当前 Dockerfile 只构建服务端与 Web。Docker 不能代替 macOS/Xcode 构建。Windows 交叉编译存在额外工具链和安装器限制，发布流程使用原生 Windows 构建机。

桌面本机构建需将 cargo/rustc 加入 PATH，在仓库根目录执行：

```sh
npm ci
npm run desktop:dev
# 发布构建
npm run desktop:build
```

Tauri 的构建钩子会先构建 Web、将其嵌入服务程序，再把当前平台服务程序复制为 sidecar。应用与服务一起打包，但服务是独立进程。退出桌面后服务继续运行，不等同于已经注册了无人登录也运行的系统服务。

Docker 构建通过、原生桌面编译通过与最终功能验收是三件事。各项证据记录在《实施与验收记录》，未实测的平台不标记完成。
