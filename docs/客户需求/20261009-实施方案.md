# 客户新增需求实施方案

日期：2026-10-09。依据：`20261009.md`、两张客户截图及本次沟通。
状态：方案评审已通过，业务代码已实现，正在完成自动化验收。

## 1. 范围与已确定方向

在现有库存台账上增加销售开单、打印、收款与欠款管理。沿用 Rust 服务、SQLite、共享 Web 界面及桌面/移动客户端。

- 一张单选择多个已建档物料，填写数量、单价，确认后自动扣库存。
- 打印先走设备的系统打印，默认 A4 纵向，无指定打印机依赖。
- 管理员可新增、改名、排序和停用单据类型；预置销售单、样品单、调货单。
- 调货单在本轮只是单据类型名称，仍使用当前单仓出库逻辑。
- 最高权限可修改客户、类型、物料、数量、价格、优惠、结算、凭证及备注，也可作废；所有已确认单据的变更保留历史。
- 提供客户、收款账户、应收、实收、欠款、补收、退款和对账。暂不扩展采购、成本利润、税务、总账或生产管理。

本方案替代原《轻量进销存产品与技术方案》中“首版不含销售金额和财务”的范围约定；原有库存事务、权限、审计及备份规则继续适用。

## 2. 数量录入

第一张图的“数量格式”是精度设置，客户可能将其理解为数量输入框。建议移除普通建档表单中的该选择，新增物料默认允许整数及最多 3 位小数。数量输入旁显示“支持小数，最多 3 位，例如 1.25”；展示时去除末尾零，例如 10、1.5、1.25。

不采用无限小数：现有数量按千分之一的整数保存，有限精度能保证库存计算、导入、导出及对账一致。超过 3 位且非零的小数明确报错，不静默舍入；多余的末尾零可规范化后接收。

升级时保留旧单据精度和数量快照。已有物料允许精度从原来的 0–2 位扩展到 3 位，余额仍为原千分之一整数，不重算、不改变数量。此扩展需走专门迁移，不能直接绕过当前“有历史后不可更改精度”的校验。历史单据按原规则展示；新单据按新规则输入和展示。导入模板将小数位数改为可选，默认 3，兼容旧模板。所有录入入口统一规则，包括收发、期初、清点和导入。

## 3. 单据类型配置

| 配置项 | 行为 |
| --- | --- |
| 名称 | 必填、非空、同一列表不可重名，作为选择项和打印标题 |
| 是否计款 | 开启则填写价格、计算应收；关闭则只记数量、默认不产生应收 |
| 启用、排序 | 停用后不能新开，历史仍可查阅 |

预置销售单计款、样品单不计款、调货单不计款，管理员可修改默认设置。所有类型确认后均扣库存，命名不自动改变库存规则；“类型名称”和“是否计款”分开配置，避免依赖名称猜测行为。

每张单保存类型名称及计款规则快照，后续改名或改变默认配置不改变历史。修改已确认单据的类型属于单据修订，需要重新校验金额；已有收款转为不计款时，必须同步处理退款，不能让收款记录消失。被引用类型只可停用，不硬删除。

## 4. 开单流程和界面

入口：工作台“开单发货”、单据列表“新建单据”。保留原入库、领用、报损等数量操作。

1. 选择单据类型和客户，填写联系人、电话、送货地址、业务日期及备注。
2. 搜索名称、编码或条码，逐行选择已建档物料；添加重复物料时合并数量。
3. 每行显示物料名称、规格、单位、可用库存、数量、单价和行金额。计款单要求单价，允许显式填写 0；不计款单隐藏金额输入。
4. 展示原金额、折扣、抹零、应收、实收、欠款。普通开单人默认无优惠和收款权限，可提交为未收款，交最高权限人员后续处理。
5. 保存草稿或“确认开单”；确认成功后显示单号，提供打印、查看单据和继续开单。

客户支持选择已有客户或快速建档，客户名称必填；欠款必须关联稳定客户 ID，防止同名混淆。临时客户也创建客户档案。历史保存名称、联系信息快照，客户后续修改不覆盖旧单。客户详情展示单据、累计应收、实收和剩余欠款。

桌面采用单据表格，数量和单价可连续键盘录入；手机采用逐行卡片与底部金额汇总。输入错误保留整张单，定位到具体行。空单、停用物料、清点锁定和库存不足均不得确认。多行必须整单成功或整单失败。

## 5. 单据状态与库存

| 状态 | 库存效果 | 操作 |
| --- | --- | --- |
| 草稿 | 不扣、不占库存 | 开单人可修改本人草稿；最高权限可修改全部 |
| 已确认 | 一次性扣库存、产生应收 | 查询、打印、收款；最高权限可修订或作废 |
| 已作废 | 冲回该单当前有效出库量 | 保留历史，不允许继续收款 |

打印和确认独立：库存只在服务端确认事务成功时扣减，取消打印、打印失败、再次打印不改变库存。打印草稿标注“草稿 · 未扣库存”，作废单标注“已作废”，确认单显示修订版本和状态。

保存草稿不保证库存，确认时再次检查。库存扣减、单据、应收、初始收款及审计在同一事务内提交。幂等键防止重复提交；并发条件扣减防止超卖；版本号防止两人改单相互覆盖。维持现有禁止负库存和清点锁定规则。

## 6. 金额及收款规则

默认人民币，不做多币种。数量最多 3 位小数，单价最多 4 位小数；采用十进制定点计算，金额保存为整数分。每行数量乘单价后按四舍五入到分，原金额为各行金额之和；不得用二进制浮点数计算钱。

折扣默认整单折扣，界面输入“折扣率 %”，100% 为原价，90% 为九折，避免“折扣”和“减免比例”混淆。折后金额四舍五入到分，折扣金额为原金额减折后金额；抹零为手动输入的非负减免金额，不能超过折后金额。

```text
原金额 = 各行金额之和
应收 = 原金额 - 折扣金额 - 抹零金额
净实收 = 有效收款之和 - 有效退款之和
欠款 = 应收 - 净实收
```

确认收款要求选择账户，支持现金、银行卡、微信、支付宝等用户自定义账户。一张单可多次收款、按多个账户拆分收款，保存日期、经办人、备注和关联单号。首轮不允许收款超过应收，也不支持预收抵扣。

欠款从金额计算，不采用一个可以手动勾选且与金额冲突的开关。界面显示“未收款 / 部分收款 / 已结清”，与草稿、已确认、已作废的业务状态分开。

客户示例：原金额 10,050 元，抹零 50 元，应收 10,000 元；现金收款 5,000 元，该账户收款增加 5,000 元，客户欠款 5,000 元。补收 5,000 元后，该单结清。

账户页面显示期间收款、退款、净收款及对应明细；销售额、应收、实收分别汇总。这是销售收款对账，不把销售额当作现金余额，也不宣称包含支出和银行全部流水。账户改名不改历史快照，已引用账户只可停用。

## 7. 最高权限改单、作废和退货

最高权限能改所有业务字段，但不能直接删除库存或资金流水、修改操作人身份、抹除审计记录。重大变更必须填写原因，并保留修改前后快照、经办人、时间和版本。

- 修改客户、备注、价格或优惠：重新计算应收与客户欠款；不重复扣库存。
- 修改物料或数量：在一个事务中先冲回旧版有效出库，再按新版扣减；按净变化校验可用库存和清点锁定，失败时整单回滚。原流水与修订流水均保留。
- 修改客户：整单应收、已收及欠款归属同步转移，历史收款的实际账户不变，保留更正记录。
- 更正收款金额或账户：冲销错误流水并新增正确流水，不能直接覆盖旧收款。
- 降低应收至净实收以下：提示超收差额，要求填写退款账户并在同一修订事务登记退款；未处理前不得保存。
- 作废：库存冲回、应收冲销；有净实收时必须同时登记退款。系统记账不自动向银行卡或支付平台发起退款，操作者需确认实际退款。
- 已完成的真实退货：建立关联原单的退货单，支持部分退货、累计数量不能超过未退数量；退货入库并按原单优惠分摊计算应收减少和退款金额，分摊尾差固定落在最后一行。普通资料更正与真实退货分开记录。

退货和改单共同校验当前有效销售量；不得把数量改到累计已退数量以下。已有退货记录的单据作废时只冲回尚未退回数量，并处理剩余有效应收和实收，避免重复入库或退款。财务报表可回溯原单、修订、退货及冲销。

## 8. 权限

| 权限 | 默认赋予 | 范围 |
| --- | --- | --- |
| 开单 | 有出库权限人员 | 新建、编辑本人草稿、确认开单、查看与打印本人单据 |
| 最高权限 | 管理员 | 全部单据、价格优惠、收退款、更正、修订、作废、退货、客户与类型配置、账户对账、凭证管理 |

首轮不增加独立财务角色；以后可从最高权限拆出收款和对账权限。普通开单人在本人单据可见单价和金额，不能通过直接请求修改优惠、资金或已确认单据。权限检查覆盖接口、附件、搜索、导出及打印数据；普通库存权限不会自动授予全量客户欠款和账户汇总。

## 9. 签字照片与备份

每张单支持最多 2 张签字/凭证照片，单张最多 10 MB，支持 JPEG、PNG、WebP；移动端支持系统拍照或相册选取。服务端检查真实图片格式和像素上限，不信任扩展名；不接受 SVG 等主动内容。

附件关联单据、上传人和时间，普通开单人可上传本人单据凭证，已确认单据附件替换/删除由最高权限操作并留痕。文件通过受权限保护的接口读取，使用随机存储名称，无公开永久地址。

原图以 SQLite BLOB 保存，随数据库的同一快照完成备份与恢复，避免数据库和独立文件不一致。旧凭证移除后保留原图及操作记录。恢复兼容旧备份：先在临时副本迁移，再验证和恢复，不修改原备份。单份数据库备份当前上限 512 MB，含原图；超过上限明确提示，不生成无法恢复的备份。上传验证成功后事务提交，不留下缺失附件。

## 10. 打印样式 V1

样稿：`20261009-销售单打印样稿.html`，浏览器打开后点击“系统打印 / 保存 PDF”。样稿为演示数据，不与当前数据库连接。

- A4 纵向、黑白为主，系统中文字体，无在线字体、图片或其他网络依赖。
- 顶部：用户配置的公司/店铺名称、联系方式、单据类型名称、单号、日期、修订版本。
- 客户区：名称、电话、联系人、地址。
- 明细区：序号、名称/规格、单位、数量、单价、金额；不打印内部可用库存。
- 汇总区：原金额、折扣、抹零、应收、实收、欠款及收款账户。
- 底部：备注、开单人、收款经办人、客户签收和签收日期。
- 不计款单隐藏价格、金额及收款汇总，保留数量与签收区。不同单位不求一个没有意义的总数量。
- 多页明细重复表头，金额汇总只出现一次，避免行内分页；长备注、长名称允许换行。

Web 使用浏览器打印；桌面及移动使用平台支持的系统打印/分享 PDF 通道，需分别验证，不能假定所有 WebView 都能直接调用 `window.print()`。打印操作不能触发库存或金额写入。浏览器模式可由系统打印对话框保存 PDF；原生 PDF 输出须实现稳定分页与中文字体支持后再交付。

## 11. 数据与技术实施

复用现有库存事务和共享 UI，不另起一套库存余额。建议以销售单为业务主单，关联库存出库单和不可变资金流水：

| 数据 | 核心内容 |
| --- | --- |
| 客户 | 稳定 ID、名称、联系信息、启用状态 |
| 单据类型 | 名称、计款、排序、启用 |
| 销售主单及明细 | 客户/类型/物料快照、状态、版本、业务日期、数量、单价、金额、优惠 |
| 单据修订 | 原版本、新版本、原因、操作者、关联库存和资金调整 |
| 收款账户及资金流水 | 收款/退款/冲销、账户快照、金额、经办人、原流水关联 |
| 退货单 | 原单/行关联、数量、优惠分摊、应收调整和退款 |
| 附件 | 单据关联、存储路径、摘要、大小、历史引用及上传人 |

原库存单可关联销售单及修订版本，不能再通过旧库存单“作废”接口独立冲回销售库存；统一走销售单入口，避免应收与库存分离。客户欠款和账户汇总以有效流水计算；如保留缓存余额，必须同事务更新并可核对重建。

金额、库存、审计与幂等结果同事务提交；图片验证后写入数据库事务。新增 SQLite 迁移，升级前完整备份；旧库存记录不自动转成带金额销售单。旧客户端继续查询库存，涉及新规则的写接口由服务端统一校验，必要时提示升级，不能允许绕过。

## 12. 开发顺序与验收

1. 数量简化、客户和类型配置、草稿/确认、多行开单、库存关联及 A4 打印。
2. 单价优惠、收款账户、部分收款与补收、客户欠款、账户对账和导出。
3. 最高权限修订、冲销退款、关联退货、签字图片、完整备份恢复及端侧验收。

三步共同完成客户需求；不得把仅实现第一步的版本描述为全部完成。

必须验证：

- 新旧数量数据精确一致，小数输入、展示、导入及清点规则一致。
- 一张单含多种物料；任一行缺货整单不扣；两人并发开单不超卖；重试不重复扣。
- 草稿与打印不扣库存；正式确认只扣一次；重复打印、取消打印无账务变化。
- 示例应收 10,000、实收 5,000、欠款 5,000；补收后结清；账户对账金额正确。
- 改价格不改库存，改数量按差额调整；失败完整回滚，并发修订有冲突提示。
- 更正账户、减价退款、已收款作废和部分退货均可追溯，账与库存一致。
- 普通账号直接调用高级接口被拒绝；附件、导出与全量报表不越权。
- 类型改名/停用、客户改名、账户改名不覆盖历史；不计款单扣库存但不产生应收。
- 备份恢复后图片、单据、修订、库存和资金流水完整一致；旧备份仍可恢复。
- A4 单页/多页、长名称、中文、无金额单据及手机/桌面打印分别验收。

## 13. 方案评审结论

评审日期：2026-10-09。结论：修正下列问题后进入实施。

- 销售关联库存只通过销售单更正、退货和作废，旧库存操作接口必须拒绝独立处理。
- 资金使用收款、退款、冲销流水；欠款由应收减净实收计算，不能以销售额代替现金。
- 已发生退货的数量或分摊金额不能被修订到已退值以下；最高权限也不能使账目违反这些约束。
- 历史单据保存名称、单位和计款快照；客户、账户和类型只停用。
- 图片以数据库 BLOB 保存，备份恢复与单据原子一致，保留原始凭证。
- 现有 E2E 解除 Git 忽略，进入 Actions；Chromium、WebKit 测试失败时不得发布。
- 原生客户端通过受控、自动登录的系统浏览器打印，平台不依赖 WebView 自身的打印支持。
- 从旧版本升级销售模块前自动完整备份；恢复旧备份先迁移临时副本。

实现与验收结果另见同目录的实施记录。


## 补充需求：部门 → 部门业务员（业绩归属）

- 管理员配置部门、部门业务员；业务员属于一个部门，不同部门允许同名业务员。
- 销售单先选部门，再选该部门启用的业务员。旧单据和暂未分配的单据允许「未指定」；指定时必须完整选择两级，后端校验所属关系。
- 业绩归属与实际登录开单人分别保存。历史名称保存快照，人员改名、调部门、停用不追改历史单据。
- 管理员可修订已确认单据的归属，保留前后版本和原因；只修改归属不重复扣库存、不改变金额。
- 单据列表、详情、修改记录和 A4 打印显示归属；管理员可查看按部门和业务员汇总的单数、业绩金额、净实收、欠款。
- 业绩金额取有效计款销售单应收，扣除退货优惠分摊，排除草稿、作废和不计款类型。净实收取收款减退款，不把收款当作销售额。
- 业务员归属用于统计，不自动赋予该业务员登录或跨用户查看单据权限。

## 补充：直接入口与可输入选项（2026-10-09）

客户原文没有要求深层配置导航。左侧常用功能直接提供「客户」，管理与设置直接提供「基础资料」。客户维护不再经过开单页 Tab；基础资料在同一层 Tab 中维护单据类型、规格、物料类型、单位、收款账户、部门、业务员和公司信息。

物料规格、类型和单位使用共享可输入下拉，允许选择候选或手输。新增 `material_options` 表，按字段与规范化名称（去首尾空白、忽略大小写）唯一；物料成功保存或 CSV 导入提交时，在业务事务中加入候选，失败全部回滚。升级从现有物料和常用单位、类型初始化候选。数量仍为计算字段，支持整数及最多三位小数，不放入字典。

字典是候选资料，物料仍保存文字值，单据保存历史快照。候选改名和删除不批量重写物料、数量或历史单据；物料资料错误从物料修改入口纠正。删除后重新手输并成功保存可重新加入。保存未改动字段不会重新加入已删除候选。类型筛选同时保留现有物料使用的分类，避免删除候选后无法筛选业务资料。已有库存记录的基本单位和精度保护继续生效。候选维护只允许管理员，保留版本冲突校验和审计。

单据类型已有独立 `sales_catalog` 实体，继续保存 ID、计款规则与版本。开单支持选择或手输；新类型必须显式选择「计款 / 不计款」，与单据在同一事务创建，重复名称复用已有实体。开单人可通过开单新增类型，配置改名、计款规则修改与停用仍由管理员操作。有关联的类型采用停用处理，保留关联；历史单据类型名称及计款快照不受配置修改影响，手输已停用名称不会绕过停用。

库存行增加「开单出库」，带入该物料并默认数量 1、价格 0，进入同一个多物料开单页。可继续添加物料；保存草稿不扣库存，确认整单才扣库存。提交成功或退出后消耗本次预填，后续新建单据不重复带入上次物料。清点锁定和开单权限继续限制该操作。

备份包含新字典表；升级前自动备份，恢复支持销售模块以前和字典模块以前的数据库，在临时副本中迁移后验证再替换业务数据。
