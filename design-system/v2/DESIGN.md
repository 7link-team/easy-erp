# Easy ERP · 设计系统 v2

面向小型工厂的库存 / 开单 / 收款操作台。桌面优先，手机采用底栏导航。

> **交付边界（2026-10-10）**：本目录是目标原型，真实应用已落地主题、字号、导航和部分手机布局，页面结构并未逐屏复刻。实际业务规则以源码及 `docs/客户需求/20261009-需求复核.md` 为准；详见第 18 节。

| 文件 | 作用 |
| --- | --- |
| `tokens.css` | 原型令牌；真实应用以 `src/theme.css` 为准：色彩、字阶、字号档位、间距、圆角、密度、渐变、动效、层级、深色主题 |
| `prototype.css` | 原型组件层 |
| `prototype.html` | 17 屏可点击原型 + 5 个弹窗（权限身份、字号三档、深浅主题均可现场切换） |
| `print.css` / `print.html` | A4 销售出货单打印稿（正常单 + 作废单两张） |
| `preview.html` | 评审用视觉稿：4 个手机壳 + 3 个桌面窗口 + 打印稿 |
| `shots/` | 36 张评审截图：`d-*` 桌面原型 · `m-*` 手机原型 · `print`/`preview` · **`app-*` 真实应用**（浅色 / 深色 / 大字号 / 弹窗 / 手机） |

本地查看：`cd design-system/v2 && python3 -m http.server 8912`，打开 `http://127.0.0.1:8912/preview.html`。

**自检命令**（项目根目录，需先起上面的服务）：

```sh
node scripts/review.mjs    # 原型静态：17 屏 × 3 视口 × 深色大字，查溢出/裁切/小字/无障碍名/控制台报错
node scripts/review2.mjs   # 原型交互：弹窗焦点与 Esc、可输入下拉、物料选择器、权限增减、字号档位
node scripts/contrast.mjs  # 环境需 ERP_USERNAME / ERP_PASSWORD；真应用：2 视口 × 2 主题 × 3 字号 × 5 页面的对比度、字号下限与横向溢出
npm run test:e2e           # 真应用与开发代理的 Playwright 端到端用例
```

## 1. 设计读解

> 日常高频操作台，用户是仓管、开单员和老板，中文、数字密集、要打印纸质单据。
> 参照系是 Stripe Dashboard 与会计账册，不是营销落地页。

三个旋钮：`变化 4 / 动效 2 / 密度 8`。克制、安静、高密度。

**对 v1 的三条否定**

1. 深绿渐变侧栏 + 浅色工作区 —— 后台模板指纹，换成浅色侧栏 + 唯一一块深色展示带。
2. 处处圆角白卡 + 阴影 —— 层级改由「底色深浅 + 1px 墨线」承担，阴影只留给浮层。
3. 暖米黄 + 中绿 + 亮金 —— 三个土黄系撞在一起。换成冷瓷灰纸面，石墨近黑做动作色，青瓷做身份色。

## 2. 字号档位（默认「中」）

工厂环境光线差、操作员年纪偏大，默认字号不能按设计师的眼睛定。桌面顶栏、手机「更多」中三档切换，**字号、控件高度、行高、触控区同步放大**，一个 `data-size` 控制全站。

| 档 | 界面基准 | 控件高 | 行高 | 主数字 |
| --- | --- | --- | --- | --- |
| 小 | 13px | 34 | 42 | 72 |
| **中（默认）** | **14px** | **38** | **46** | **78** |
| 大 | 15px | 44 | 54 | 84 |

触屏设备在各档基础上再加一档高度。

## 3. 色彩

**纸面** `#FFFFFF → #F8F9F9 → #F1F3F3 → #E7EAEA`，冷中性，不带黄。
**墨线** `#E8EBEB` 发丝线 / `#D8DDDD` 结构线 / `#C2C8C8` 控件线。
**墨色** `#0E1113` 主 / `#353B3D` 次 / `#6A7173` 标签（对白 5.1:1）/ `#99A0A1` 占位。

**身份色** `--brand #0B8F7D` 翡翠：主按钮、选中、焦点、品牌标记。按钮用 `--grad-primary` 渐变 + 同色相辉光。

**七色宝石色环** `c1…c7`，每色自带一条渐变 `g1…g7`：

| | 色 | 承载的语义 |
| --- | --- | --- |
| c1/c2 | 翡翠 `#0B8F7D` · 亮青 `#14BDA4` | 货、正常、已结清、销售单 |
| c3 | 靛蓝 `#2563A8` | 流水、出入库、样品单 |
| c4 | 紫晶 `#6B4FC4` | 清点、设置域、调货单 |
| c5 | 琥珀 `#D99B1F` | 预警、库存偏低、财务域 |
| c6 | 珊瑚 `#E0663C` | 退货、让利 |
| c7 | 朱砂 `#D6412F` | 欠款、超库存、作废 |

**色相承载语义，不是随机上色**，一屏最多同时出现 4 个色相。落点：侧栏图标按业务域着色、菜单选中为实心渐变药丸、四块 KPI 各一色相（连趋势折线一起换色）、单据类型标签按类型着色、进度条与业绩条用对应渐变。

**渐变全部多光源**，禁止 45° 两色直线渐变。展示带是四层叠加：左下翡翠光斑 + 右上靛蓝光斑 + 底部琥珀热点 + 深青到墨蓝的底色。投影带本体色相（`--glow-brand`），不用黑色半透明。

**深色主题** `[data-theme="dark"]` 只翻转纸面与墨色，品牌与语义保持同一色相。

## 4. 字体与数字

中文走系统字体（PingFang SC / 微软雅黑）—— 桌面端不加载 5MB 中文 webfont，这是工程决定，不是妥协。拉丁与数字用 **IBM Plex Sans / Mono**：工业感、tabular 数字优秀，与黑体同族气质。

字阶基准 **13px**（不是 16px，ERP 要密度）：11 标签 / 12 辅助 / 13 表格控件 / 14 正文 / 16 区块 / 20 面板 / 24 页面 / 32 KPI / 40 单据总额 / 56 / **72 主数字**。

一屏只许出现一次 72px 主数字。所有数字 `tabular-nums`，账要对得齐。

## 5. 密度与尺寸

桌面控件高 **34px**（v1 是 44px，桌面端过高），表格行 42px；`@media (pointer: coarse)` 自动放大到 44 / 52px，不靠断点猜。

圆角内紧外松：状态章 3px（接近方形，像盖章）· 纸张 4px · 控件 6px · 弹窗 14px。

## 7. 微交互

动效只做两件事：**回应操作、指示状态**。无装饰动画，全部受 `prefers-reduced-motion` 保护。

- 主按钮：hover 抬 1px + 同色相辉光扩散；按下回落
- 表格行：hover 从中心滑出 2px 身份色竖条，指明「这一行」
- 账本栏：hover 时趋势折线重新描绘，端点放大
- 展示带柱图：hover 高亮 + 数值气泡
- 分段控件：白色指示块滑动，不是整块重绘
- 入场：区块错峰 55ms 淡入上移，主数字 760ms 缓出滚动，各自只跑一次
- 顶栏：滚动后转毛玻璃

## 8. 信息架构（v2 重划）

v1 的「开单与收款」把业务和财务混在一起，「记录」太笼统，且缺客户与退货入口。按业务域重划为五区，菜单名一律 2–4 字：

| 区 | 菜单 | 可见角色 |
| --- | --- | --- |
| 概览 | 工作台 | 全部 |
| 销售 | 开单 · 单据 · 客户 · 退货 | 开单员见前三项；退货仅管理员 |
| 库存 | 物料 · 收发 · 清点 · 记录 | 仓管见全部；开单员只见物料与记录 |
| 财务 | 收款 · 账户 · 业绩 | 仅管理员 |
| 设置 | 基础资料 · 人员 · 备份 · 规范 | 仅管理员 |

**基础资料是一个通用字典管理器**，不是单据类型一张表。左侧 7 本字典（单据类型 / 收款账户 / 部门 / 业务员 / 物料分类 / 计量单位 / 常用规格）共用同一套表格与新增、改名、排序、停用操作；开单与建档时输入的新值，提交成功后自动收录。被引用的条目只能停用，不能删除。

**权限不可见就不渲染**，不置灰 —— 置灰等于告诉用户「这里有你不能用的东西」。整组被隐藏时组标题一并消失。原型顶栏提供视角切换（管理员 / 开单员 / 仓管）实时演示。

## 9. 手机形态

不是把桌面压窄，是换掉导航、表格与页头：

- **底部 Tab Bar** 五项，中间「开单」抬起为实心动作块；毛玻璃 + 安全区
- **工作台首屏**：深色展示带顶到屏幕边、吃掉状态栏，内嵌 App Bar
- **指标** 2×2 磁贴；**列表** 全出血白块，分隔线左侧内缩
- **表格转列表行**：每张表按语义指定主信息 / 金额 / 状态的落位，不做通用塌陷
- **开单**：逐行卡片 + 底部吸附结算条（应收 + 保存并打印），像收银结算

## 10. 用词规范（傻瓜式优先）

界面上不出现会计行话和技术词。全站过了一遍：

| 原词 | 问题 | 改为 |
| --- | --- | --- |
| 已连接库存电脑 | 连接的是服务不是机器；用户关心的是「数据有没有在保存」 | **库存服务** + 当前访问地址；不以连接状态承诺数据已保存 |
| 收发 / 收发记录 | 行话 | 出入库 / 出入库记录 |
| 低于安全库存 · 安全线 | 行话 | 库存偏低 · 预警线 |
| 净实收 · 销售应收 · 回款率 | 会计词 | 实际收到 · 应收货款 · 已收比例 |
| 账龄 | 行话 | 欠了多久 |
| 结存 · 变动 | 行话 | 剩余库存 · 增减 |
| 累计收款 − 累计退款 = 净收款 | 会计式 | 收款合计 − 退款合计 = 实际净收 |
| 今日净流入 | 会计词 | 今天实际收到 |
| 字典 | 技术词 | 选项清单 |
| 是否计款 / 计款 / 不计款 | 行话 | 要不要收款 / 要收款 / 不收款 |
| 已用单数 · 引用物料 | 行话 | 已开单数 · 用到的物料 |
| 视角 | 含糊 | 当前身份 |
| 被引用的只能停用 | 技术说法 | 已经用过的只能停用，老单据照常能查 |

说明文字一律写成大白话，例如「开单后自动减库存，并记一笔应收款」而不是「确认后扣库存并产生应收」。

## 11. 基础资料 = 选项清单（通用字典）

左侧 7 本清单（单据类型 / 收款账户 / 部门 / 业务员 / 物料分类 / 计量单位 / 常用规格）共用同一套表格与操作：

- **编辑** —— 名称、排序、说明、以及该清单自己的字段（如单据类型的「要不要收款」）全部可改，不是只能改名
- **要不要收款** 等布尔项做成行内开关，直接点并二次确认；规则变化只影响后续新单，历史单据保留快照、不追溯改账
- **排序** —— 行号位置悬停变拖拽手柄
- **停用 / 启用** —— 停用后不能再新开，老单据照常查
- **删除** —— **只在「没用过」（已开单数 / 用到的物料 = 0）时出现**；用过的那行显示一个 `?`，鼠标悬停说明「已经用过，删掉会让老单据对不上，所以只能停用」

规则与现有物料删除一致：零引用可删，有历史只可停用。

## 14. 评审结论

原型静态检查覆盖 17 屏 × 3 视口，并在工作台补查深色大字号；交互检查另验证字号切换。不是所有组合的全量覆盖：

| 检查 | 范围 | 结果 |
| --- | --- | --- |
| `review.mjs` | 横向溢出、文本裁切、字号下限、无障碍名缺失、控制台报错 | **0 项** |
| `review2.mjs` | 弹窗开关与焦点管理、Esc、滚动锁、可输入下拉、物料选择器、权限增减、字号档位 | **0 项** |

修复过程中发现并解决的真实缺陷：

1. `--grad-primary` 令牌被误删 → 主按钮渲染为透明，全局不可见
2. `[hidden]` 被 `.nav-item{display:flex}` 覆盖 → **权限隐藏失效，开单员能看到财务与设置菜单**
3. `.gutter{position:relative}` 覆盖表头 sticky → 序号列错位
4. 9–10px 硬编码字号绕过字号档位 → 统一收口到 `--t-min`，全站无小于 11px 的文字
5. `id` 属性被写进 `class` 内 → 3 个表单控件失去 label 关联
6. 物料选择器选项网格列序错位 → 库存数显示在名称左边
7. 深色模式下展示带主数字暗底暗字 → 拆出 `--on-band` 固定白

## 15. 可访问性与规范基线

已按 Web Interface Guidelines 核对并修正：

- 跳到主内容链接；`main[id][tabindex="-1"]`
- 所有图标按钮带 `aria-label`；表单控件 `label[for]` 绑定或 `aria-label`
- 搜索改为 `form[role=search] > input[type=search]`，带 `autocomplete="off"`
- 错误用 `aria-invalid` + `aria-describedby` 指向行内中文提示
- 焦点环统一 `:focus-visible`，2px 身份色，从不移除轮廓
- 无 `transition: all`；只过渡 `transform` / `opacity` / 颜色
- `touch-action: manipulation` + 去除点击高亮；触控目标 ≥ 44px
- `color-scheme` 与 `theme-color` 随主题；原生 `select` 在深色下显式配色
- `env(safe-area-inset-*)` 覆盖顶栏、底栏与吸附条

## 17. 回归验收

设计换肤后跑了项目原有的 Playwright 全量 E2E。**测试里写死旧设计的断言已同步更新**，并顺手把两处脆弱断言改成读设计令牌：

| 原断言 | 问题 | 改为 |
| --- | --- | --- |
| 控件高 `toBe(44)` / `toBe(48)` | 写死像素，字号档位一变就挂 | 读 `--h-control` 计算值；窄屏另加「≥ 44px」底线断言 |
| 统计卡文字 `rgb(225,241,232)` | 写死旧色 | `rgba(255,255,255,0.72)`（`--on-band-2`） |
| 展示带 `toContain("linear-gradient")` | 只认单层渐变 | 同时要求 `radial-gradient` 与 `linear-gradient`，锁住「多光源」这条规则 |
| 菜单名、侧栏分区 | 旧名与旧分组 | 新的五域结构与短菜单名 |

回归过程中暴露并修掉的真实缺陷：

1. `.mobile-more` 的默认隐藏规则排在手机媒体查询**之后**，把手机「更多」入口整个盖没了 —— 改成显式 `min-width` 断点，与书写顺序解耦
2. 触控放大只写了 `(pointer: coarse)`，桌面浏览器缩到手机宽度时控件仍是 38px —— 改为 `(pointer: coarse), (max-width: 760px)`
3. `controls.css` 在窄屏另开了一套 `--control-height: 48px`，与令牌打架 —— 去重，统一走 `--h-control`
4. 按钮垂直内边距撑破 `min-height`，实际高 39px ≠ 令牌 38px —— 高度统一由 `min-height` 决定
5. 弹窗底部操作条、下拉浮层、帮助气泡仍写死白底，深色模式下是白块 —— 全部收口到 `--paper-0`

`sales.css` 里的打印配色**故意保留写死值**并加了注释：打印永远是白纸，不该跟随深浅主题。

保留开单内「收款与欠款」作为管理员快捷入口；本轮不重构独立业务页面。
